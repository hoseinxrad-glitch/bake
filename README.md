# چت‌یار — سایت پیام‌رسان

یک اپلیکیشن پیام‌رسان کامل با چت لحظه‌ای (Real-time)، پشتیبانی از گفتگوی خصوصی (۱ به ۱) و گروهی، احراز هویت با JWT و پایگاه‌داده‌ی SQLite.

## معماری

- **بک‌اند:** Python + FastAPI + WebSocket + SQLAlchemy + SQLite
- **فرانت‌اند:** HTML/CSS/JavaScript خالص (بدون فریم‌ورک، اجرا در هر مرورگری)
- **احراز هویت:** JWT (رمز عبور با bcrypt هش می‌شود)

## قابلیت‌ها

- ثبت‌نام و ورود کاربران
- جستجوی کاربران و شروع گفتگوی خصوصی
- ساخت گفتگوی گروهی و کانال از داخل رابط کاربری
- ارسال و دریافت پیام به‌صورت لحظه‌ای با WebSocket
- تاریخچه‌ی پیام‌ها (ذخیره در دیتابیس)
- وضعیت آنلاین/آفلاین کاربر
- **پنل ادمین:** آمار کلی (تعداد کاربران، آنلاین‌ها، گفتگوها، پیام‌ها)، مدیریت کاربران (مسدود/رفع مسدودیت، ارتقا به ادمین، حذف)، مدیریت گفتگوها (مشاهده و حذف)
- **ارسال عکس، فایل و پیام صوتی:** دکمه‌ی 📎 برای انتخاب فایل از سیستم (تا ۲۵ مگابایت) و دکمه‌ی 🎤 برای ضبط مستقیم صدا از مرورگر؛ فایل‌ها روی دیسک سرور (پوشه‌ی `backend/uploads`) ذخیره می‌شوند
- **دستیار هوشمند (AI):** یک مخاطب ویژه به نام «دستیار هوشمند» که با کلیک روی دکمه‌ی بالای سایدبار باز می‌شود؛ **متن‌به‌متن و صوت‌به‌صوت** — اگر پیام متنی بفرستی جواب متنی می‌گیری، اگر پیام صوتی بفرستی، صدایت را می‌شنود و با صدا جواب می‌دهد (گفتار→متن، متن→متن، متن→گفتار — هر سه با مدل جداگانه و قابل‌تنظیم از پنل ادمین)
- **ساخت گروه و کانال از داخل رابط کاربری:** دکمه‌ی «+ ساخت گروه یا کانال» در سایدبار؛ در **گروه** همه‌ی اعضا پیام می‌فرستند، در **کانال** فقط سازنده پیام می‌فرستد و بقیه فقط می‌خوانند
- **افزودن خودکار مخاطب:** وقتی کسی برای اولین بار برایت پیام می‌فرستد، گفتگوی جدید خودش (بدون رفرش صفحه) در سایدبارت ظاهر می‌شود؛ لیست کاربران هنگام جستجو شامل کاربران آفلاین هم می‌شود (نه فقط آنلاین‌ها)
- **متن پررنگ:** هرجا (چه خودت چه دستیار هوشمند) بین دو ستاره بنویسی، مثل ‎`**مهم**`‎، در چت به‌صورت **بولد** نمایش داده می‌شود
- **پنل ادمین برای همه (با رمز):** دکمه‌ی «ادمین» برای همه‌ی کاربران لاگین‌شده دیده می‌شود؛ برای ورود باید رمز پنل را وارد کنند (پیش‌فرض: `132465798`؛ با متغیر محیطی `ADMIN_PANEL_PASSWORD` قابل تغییر است)
- **پنل ادمین:** آمار کلی، مدیریت کاربران (مسدود/رفع مسدودیت/ارتقا/حذف)، مدیریت گفتگوها، تغییر مدل و کلید(های) API دستیار هوشمند بدون ری‌استارت سرور، تغییر مدل‌های STT/TTS و صدای دستیار، تغییر رنگ اصلی اپ برای همه‌ی کاربران
- **حالت موبایل:** رابط کاربری روی صفحه‌های کوچک (گوشی) به‌صورت تک‌ستونه می‌شود — لیست گفتگوها و صفحه‌ی چت هرکدام تمام‌صفحه نشان داده می‌شوند و با دکمه‌ی بازگشت (→) بین آن‌ها جابه‌جا می‌شوی

## انتشار روی اینترنت (گیت‌هاب پیجز + رندر)

راهنمای کامل قدم‌به‌قدم در فایل [`DEPLOY.md`](./DEPLOY.md) است. خلاصه: بک‌اند روی [Render](https://render.com) دیپلوی می‌شود، فرانت‌اند (که نیازی به بیلد ندارد) روی [GitHub Pages](https://pages.github.com) — و تنها چیزی که باید عوض کنی، آدرس بک‌اند در فایل `frontend/config.js` است.

### فعال‌سازی دستیار هوشمند (از طریق GapGPT، با چند کلید)

1. تا ۱۰ کلید API از پنل [GapGPT](https://gapgpt.app) بردارید.
2. قبل از اجرای بک‌اند، همه‌ی کلیدها را با کاما از هم جدا کرده و در متغیر محیطی `GAPGPT_API_KEYS` بگذارید:
   ```bash
   # ویندوز (CMD)
   set GAPGPT_API_KEYS=sk-key1,sk-key2,sk-key3,sk-key4,sk-key5,sk-key6,sk-key7,sk-key8,sk-key9,sk-key10

   # ویندوز (PowerShell)
   $env:GAPGPT_API_KEYS="sk-key1,sk-key2,sk-key3,sk-key4,sk-key5,sk-key6,sk-key7,sk-key8,sk-key9,sk-key10"

   # macOS/Linux
   export GAPGPT_API_KEYS="sk-key1,sk-key2,sk-key3,sk-key4,sk-key5,sk-key6,sk-key7,sk-key8,sk-key9,sk-key10"
   ```
   (اگر فقط یک کلید داری، کافیست همان قبلی یعنی `GAPGPT_API_KEY` را تنظیم کنی.)
3. متغیر مدل را هم مثل قبل تنظیم کنید (همان اسم دقیقی که از لیست مدل‌های GapGPT پیدا کردید، مثلاً کلود فابل ۵):
   ```bash
   set GAPGPT_MODEL=اسم-دقیق-مدل-کلود-فابل-۵
   ```
4. سپس مثل همیشه اجرا کنید: `uvicorn main:app --reload --port 8000`

**نحوه‌ی کار چرخش کلید:** هر بار که دستیار هوشمند پیامی دریافت می‌کند، یکی از کلیدها را به‌ترتیب چرخشی امتحان می‌کند. اگر آن کلید با خطا یا محدودیت نرخ مواجه شود، خودکار سراغ کلید بعدی می‌رود (تا حداکثر تعداد کلیدهایی که دادید). این باعث می‌شود مجموع محدودیت نرخ شما عملاً چند برابر شود.

اگر هیچ کلیدی تنظیم نشود، دستیار هوشمند به‌جای کرش کردن، یک پیام راهنما برمی‌گرداند و بقیه‌ی اپلیکیشن بدون مشکل کار می‌کند.

### تغییر مدل بدون ری‌استارت سرور

دیگر لازم نیست برای تغییر مدل، متغیر محیطی `GAPGPT_MODEL` را عوض کنی و سرور را ری‌استارت کنی. از پنل ادمین (`admin.html`) وارد تب «دستیار هوشمند» شو، اسم دقیق مدل جدید را بنویس و «ذخیره و اعمال» را بزن — همان لحظه فعال می‌شود و برای همیشه (حتی بعد از بستن و روشن کردن دوباره‌ی سرور) در دیتابیس ذخیره می‌ماند. متغیر محیطی `GAPGPT_MODEL` فقط به‌عنوان مقدار پیش‌فرض اولیه (وقتی هنوز چیزی از پنل ذخیره نشده) استفاده می‌شود.

### تنظیم صوت دستیار هوشمند (STT / TTS)

برای اینکه دستیار بتواند پیام صوتی را بشنود و با صدا جواب بدهد، دو مدل اضافی لازم است — این‌ها هم از همان تب «دستیار هوشمند» در پنل ادمین قابل تنظیم‌اند:
- **مدل STT (گفتار به متن):** پیش‌فرض `whisper-1`
- **مدل TTS (متن به گفتار):** پیش‌فرض `tts-1`
- **صدا (voice):** پیش‌فرض `alloy`

اگر این مدل‌ها روی حساب GapGPT شما در دسترس نباشند (مثل مشکلی که قبلاً با اسم مدل چت داشتیم)، همان روش قبلی را تکرار کن: با دستور `curl .../v1/models` لیست مدل‌های در دسترس را بگیر، دنبال کلمه‌ی `whisper` یا `tts` بگرد، و اسم دقیق را در پنل ادمین بگذار. اگر تبدیل صدا با خطا مواجه شود، دستیار به‌جای کرش کردن، حداقل پاسخ متنی را برایت می‌فرستد.

### دسترسی به پنل ادمین

دکمه‌ی «ادمین» برای **همه‌ی کاربران لاگین‌شده** در سایدبار دیده می‌شود. با کلیک روی آن، یک صفحه‌ی رمز باز می‌شود؛ رمز پیش‌فرض `132465798` است (با متغیر محیطی `ADMIN_PANEL_PASSWORD` قابل تغییر). همچنین اولین کاربری که در سیستم ثبت‌نام کند به‌طور خودکار «ادمین واقعی» می‌شود و بدون نیاز به رمز هم به پنل دسترسی دارد.

## ساخت گروه و کانال

از داخل خود اپ: روی دکمه‌ی «+ ساخت گروه یا کانال» در سایدبار بزن، نوع (گروه/کانال) و اعضا را انتخاب کن. از طریق API هم می‌شود:

```bash
curl -X POST http://localhost:8000/rooms \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"is_group": true, "room_type": "channel", "name": "اطلاعیه‌ها", "member_ids": [2,3,4]}'
```

## راه‌اندازی بک‌اند

```bash
cd backend
python3 -m venv venv
source venv/bin/activate      # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

سرور روی `http://localhost:8000` بالا می‌آید. مستندات API خودکار در `http://localhost:8000/docs` قابل مشاهده است.

## راه‌اندازی فرانت‌اند

فرانت‌اند نیازی به بیلد ندارد. کافیست فایل `frontend/index.html` را از طریق یک سرور استاتیک ساده باز کنید (به‌خاطر محدودیت‌های مرورگر، بهتر از باز کردن مستقیم فایل است):

```bash
cd frontend
python3 -m http.server 5500
```

سپس در مرورگر به آدرس `http://localhost:5500` بروید.

> برای اجرای محلی (روی سیستم خودت) نیازی به تغییر چیزی نیست — فایل `frontend/config.js` از قبل روی `localhost:8000` تنظیم شده. فقط برای انتشار روی اینترنت (گیت‌هاب پیجز/رندر) باید همین فایل را عوض کنی؛ به [`DEPLOY.md`](./DEPLOY.md) نگاه کن.

## نکات امنیتی قبل از انتشار عمومی (Production)

- مقدار `SECRET_KEY` در `backend/auth.py` را با یک مقدار تصادفی و امن جایگزین کنید و آن را در متغیر محیطی (env variable) نگه دارید.
- `allow_origins=["*"]` در CORS را به دامنه‌ی واقعی سایت محدود کنید.
- رمز پنل ادمین (`132465798`) را قبل از انتشار عمومی حتماً با متغیر محیطی `ADMIN_PANEL_PASSWORD` عوض کنید — این رمز الان برای هر کاربر لاگین‌شده‌ای کار می‌کند.
- برای هاست رایگان: بک‌اند روی Render/Railway/Fly.io و فرانت‌اند روی Vercel/Netlify/GitHub Pages قابل استقرار است. توجه کنید در بسیاری از پلن‌های رایگان، فایل SQLite با هر دیپلوی مجدد ممکن است پاک شود؛ برای پایداری داده در پروداکشن به یک دیتابیس رایگان مثل Supabase یا Neon (Postgres) مهاجرت کنید.
